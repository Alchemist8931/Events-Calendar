## 3. Модель данных

```
users ──┬── teams (is_personal | обычная)
        │      ├── team_members (owner | member)
        │      ├── team_invites (код на 14 дней)
        │      └── events → materials / actions / attachments
        └── billing_accounts → billing_transactions
                             → team_charges
```

**Ключевые правила**

- Личный календарь создаётся автоматически при регистрации, бесплатен всегда,
  push по нему не рассылается (уведомлять некого).
- Обычная команда: **100 ₽ за участника в месяц**, первые 30 дней бесплатно.
- Платит **владелец** команды со своего баланса.
- Пользователь может состоять в любом числе команд.
- Не хватило денег → команда `suspended`: данные видны, запись заблокирована.
  Пополнение баланса снимает приостановку автоматически.

Тариф и длительность триала лежат в `app_settings`
(`price_per_member_kopecks`, `trial_days`) — меняются без правки кода.

## 4. Что нового в интерфейсе

**Переключатель календарей** — горизонтальная лента чипов под шапкой:
«Все календари» / «Личный» / каждая команда. У каждой команды свой стабильный
цвет, он же используется в точках календаря и полосках карточек.

**Режим «Все календари»** — мероприятия всех команд на одной сетке; над названием
события показывается команда её цветом. В точках дня — до трёх разноцветных
маркеров по числу задействованных команд.

**Команды** (иконка людей в шапке) — список с числом участников и стоимостью,
создание команды, вступление по коду. Карточка команды: биллинг, участники,
генерация кода приглашения, переименование, удаление, выход.

**Баланс** — в меню профиля; отдельный экран с историей операций.

**Push** — название команды выведено первой строкой заголовка (`▸ Команда`),
поэтому видно прямо в шторке. Рассылка идёт строго участникам этой команды.

## 5. Биллинг: как работает

```
Создание команды  → trial_ends_at = now() + 30 дней, запись team_charges(status='trial')
Ежедневно 02:23   → charge_due_teams()
                     ├── денег хватает  → списание, next_charge_at += 30 дней, status='paid'
                     └── не хватает     → team.status='suspended', status='failed'
Пополнение        → topup_balance() снимает suspended, если суммы достаточно
```

Списание считается по числу участников **на момент списания**. Добавили человека
в середине периода — доплаты не будет, он попадёт в следующий счёт.

### Приём платежей — подключён

Развёрнуты две Edge Function:

- `payment-create` (требует JWT) — создаёт платёж в ЮKassa, возвращает ссылку на оплату
- `payment-webhook` (публичная) — принимает `payment.succeeded`, проверяет платёж
  через API ЮKassa и зачисляет средства

Осталось задать три секрета и зарегистрировать вебхук — см. **YOOKASSA.md**.

Ручное пополнение (пока секреты не заданы):
```sql
SELECT public.topup_balance('<user_id>', 100000, 'Ручное пополнение'); -- 1000 ₽
```

## 7. Проверенное тестами

- **Изоляция команд**: пользователь A создал команду и мероприятие → пользователь B
  их не видит (`teams_visible: 2, secret_visible: 0`). Тест с `ROLLBACK`.
- **Биллинг**: хватает средств → списание и перенос даты; не хватает → `suspended`.
- **Триггеры** после отзыва прав продолжают писать журнал.
- **Миграция данных**: 4 пользователя, 5 команд, 2 мероприятия на месте.

### Два бага, найденных и исправленных при тестировании

1. `INSERT ... RETURNING` в `create_team` падал: SELECT-политика требовала
   членства, которого на момент вставки ещё нет. Добавлено `owner_id = auth.uid()`
   в политику чтения `teams` и `team_members`.
2. `create_team` был `SECURITY INVOKER` и не мог писать в `team_charges`
   (таблица закрыта на запись для пользователей — и правильно). Переведён
   в `SECURITY DEFINER` с явной проверкой `auth.uid()` и лимитом 20 команд.

## 8. Что стоит доделать перед публичным запуском

| Приоритет | Задача |
|---|---|
| Высокий | Оферта, политика перс. данных, уведомление в РКН — без них ЮKassa не подключит боевой магазин |
| Средний | Приглашение по email вместо только кода (поле `team_invites.email` уже есть) |
| Средний | Возврат/пропорциональный пересчёт при удалении участника в середине периода |
| Низкий | Годовой тариф со скидкой |
| Низкий | Лимиты бесплатного тарифа, если личный календарь начнут использовать как хранилище |

Закрыто в этой итерации: вебхук ЮKassa, уведомления о биллинге, передача владения командой.

**Про роли внутри команды** намеренно оставлено плоско: владелец управляет
составом и платит, остальные равны в правах на мероприятия. Это соответствовало
исходному ТЗ, и усложнять стоит только когда появится реальный запрос от клиентов.
